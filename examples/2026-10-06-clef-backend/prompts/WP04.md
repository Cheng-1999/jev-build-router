# WP04 — Docs and disclosure for the Clef backend

## Why

WP01–WP03 added `DECISION_BACKEND` (`jev` default, `clef` = Cloudflare Workers
AI), wired both TypeSafe rungs through it, and taught the eval tools to score
Jev, hosted Clef and a local Clef server. The project documents and discloses
every outside service that sees users' captions. Nothing is switched on in
production by this build; the docs must say so plainly.

Read `ig_places/decision.py`, the diffs of WP02/WP03 (`git diff`), and the
Cloudflare announcement (https://blog.cloudflare.com/clef-decision-models/)
before writing.

## What to change

`ops/reports/NAMING_ARCHITECTURE.md`
- Tier 0c section and the category-select section: a short paragraph each on
  the backend switch — env names, fail-closed rule (unknown backend = rung
  off, never a fallback), pinned model names, price per million input tokens
  (Jev 0.042, clef 0.24, clef-flash 0.09), and that the measured figures in
  the section are **Jev's**; Clef figures go in only after a per-source
  before/after run with `tools/typesafe_eval.py --backend ...` (rule 1). Do not
  invent numbers.

`ops/CREDENTIALS.md`: rows for `CLOUDFLARE_ACCOUNT_ID` and
`CLOUDFLARE_AI_TOKEN` in the existing table format — what it is for (tier 0c /
category on the Clef backend), whether it expires (Cloudflare API tokens can be
created with or without an expiry: recommend a scoped Workers AI token with an
expiry and say where to rotate it), what alert fires when it fails (the
existing `typesafe` alert kind), and that it is only needed when
`DECISION_BACKEND=clef`.

`templates/privacy.html`, the `#processors` list item "AI 店名辨識 / AI naming":
add Cloudflare Workers AI beside TypeSafe for "choosing among candidate names
and categories", in both the Chinese and English text on that line, in the
same style. Keep it accurate: the caption text and candidate strings are what
is sent (see `typesafe_select` "WHAT REACHES THE MODEL").

`ops/reports/COUNTRY_COMPLIANCE_NOTES_2026-09-25.md`: a dated note that
Cloudflare becomes a processor of caption text when the Clef backend is
enabled, its stated no-retention / no-training guarantee for Workers AI
requests (quote the announcement's wording, attributed), and that enabling it
in production is gated on this disclosure being live.

## Tests

`PYTHONIOENCODING=utf-8 ./.venv/bin/python smoke_test.py` stays green (the
privacy page has checks: data-theme, safe areas, reachability). Open nothing
else.

## Out of scope

Any code change. Any claim that Clef is enabled in production. Translations
beyond the two languages the privacy page already carries inline.
